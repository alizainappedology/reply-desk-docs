Privacy and security

Back to README

Supported boundary

Reply Desk is a single-user local app. FastAPI binds to 127.0.0.1:8765; the supplied Ollama startup binds to 127.0.0.1:11434. Do not expose it through public tunnels, a shared LAN interface, or a public reverse proxy without redesigning authentication and account isolation.

Host validation and a per-process request token protect local requests, but they are not user authentication. Another process or user with access to the same computer can potentially access local services or browser storage.

Credentials

Gmail app passwords are entered through account settings and held in the backend's CONFIG memory. They are never written to the app's browser persistence or intentionally logged. The password field clears after successful connection. Disconnect or stop the backend to clear the stored configuration.

Python strings are not explicitly memory-zeroed; clearing the configuration is not a guarantee against memory inspection. The app uses an app password, not OAuth. The app password must be issued for the connected account. Replace credentials exposed through chats, screenshots, commits, or other unintended locations.

Email and AI data

Gmail connections use TLS IMAP and SMTP. AI requests use the loopback Ollama chat endpoint. The selected message and optional bounded thread context are processed locally, not sent to a paid cloud model.

When the supplied script starts Ollama, it disables cloud functionality. If it reuses an existing Ollama process, that process's configuration is retained. The app's generation model is restricted to llama3.2:3b.

Email and conversation content are treated as untrusted prompt context. React renders content as text, not executable email HTML. These measures reduce prompt injection and browser execution risks, but a local model can still make mistakes or follow malicious content incorrectly. Review its output.

Browser persistence

Profile, current drafts, version history, and send-request metadata are stored in localStorage as readable JSON. This data is not encrypted by the application and is accessible to users or software with access to that browser profile.

History is scoped to mailbox/UIDVALIDITY and capped at 200 versions per mailbox. Disconnect does not remove browser history. Clear local history in the UI or clear the site's browser data to remove it. Clearing browser history does not delete Gmail messages or drafts. Profile is stored separately and may require clearing site data for complete removal.

Sending and duplicate prevention

Sending requires explicit UI confirmation and server validation of the recipient, confirmation flag, and request ID. The server records attempted IDs before calling SMTP and rejects a repeat during that process lifetime.

This is not a durable exactly-once guarantee. A timeout can occur after Gmail accepted a message. A restart clears attempt tracking, and a different ID can send another copy. Inspect Gmail Sent before retrying ambiguous results. Saving creates new drafts; sending does not delete an earlier draft.

Batch generation does not send automatically. There is no scheduled sending or background inbox polling.

File access and responses

Only the React build and /assets are served. The server sets no-store caching, nosniff, and a content security policy restricting scripts to the same origin and preventing framing. POST bodies are checked against a 128,000-byte limit after reading them. Apache access is denied by the project's .htaccess when supported by the Apache configuration.

Repository ignores exclude credentials files, runtimes, model downloads, dependency directories, caches, and preview artifacts. Ignore rules are not a substitute for inspecting staged changes.

Reporting a problem

Report a minimal reproduction to the repository owner without including app passwords, tokens, private message bodies, or recipient addresses. For credential exposure, revoke the affected password first. This repository currently has no dedicated private vulnerability reporting workflow.
