Components

flowchart LR
    Browser[React browser UI] -->|JSON and process request token| API[FastAPI on 127.0.0.1:8765]
    Browser --> Storage[Browser localStorage]
    API -->|TLS IMAP 993| Gmail[Gmail mailbox]
    API -->|TLS SMTP 465| SMTP[Gmail sending]
    API -->|Local HTTP 11434| Ollama[Ollama / llama3.2:3b]
    API --> Assets[Built React assets]

server.py serves both the API and React production build. FastAPI synchronous route handlers run blocking Gmail and model operations in worker threads. The app stays on one origin, so production does not require CORS.

Ollama uses a separate background process. local-ai.ps1 sets loopback binding, the project model directory, an 8192-token context setting, and disabled cloud functionality when starting that process. If an Ollama server already exists on port 11434, the script reuses it; its configuration is not changed.

State and persistence

Backend state is process-global and intended for one local user:

  • CONFIG: connected email, app password, and model.
  • TOKEN: random process request token injected into the served HTML meta tag.
  • SENDS: attempted send IDs with pending, sent, or unknown outcomes.
  • LOCK: guards shared credential and send-state mutations.

All are lost when the server restarts. Run one server process; multiple workers would have separate credentials, tokens, and send tracking.

The React store exposes subscriptions through useSyncExternalStore. It stores messages, the selected email, editor text, filters, profile, versions, busy state, and batch state. Browser storage keys remain:

  • replydesk.profile
  • replydesk.drafts.<mailbox>
  • replydesk.history.<mailbox>

The mailbox namespace includes the email address and IMAP UIDVALIDITY. History retains the newest 200 versions. Browser state is not a database and has browser-dependent storage limits.

Mail flow

Each mailbox operation opens a fresh encrypted IMAP connection. Inbox fetches use read-only selection and BODY.PEEK[]. Search returns message UIDs and the app loads a 20-message page.

Conversation lookup fetches X-GM-THRID, selects the special-use All Mail folder read-only, searches that thread ID, and reads its latest six messages. Inbox body text is bounded to 16,000 characters; each conversation entry is bounded to 3,500 characters.

Generation sends untrusted mail context separately from owner instructions to local Ollama /api/chat. Draft, summary, and refinement tasks use different prompts. Generation is nonstreaming with a 300-second timeout. Short generation uses up to 512 output tokens; Detailed uses up to 900. Signature insertion is handled after generation.

Saving appends a new message flagged \Draft into Gmail's special-use Drafts folder. Sending uses SMTP_SSL and the same reply construction. Both preserve In-Reply-To and References when the original has a Message-ID.

Serving and build

Vite builds into ignored frontend/dist. FastAPI injects the process token into that build's HTML and serves bundled files from /assets. The server does not expose source files, .venv, model files, or arbitrary filesystem paths. .htaccess denies Apache access to the project.
