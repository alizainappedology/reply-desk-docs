Development

Install and run

From the project root, run setup-app.ps1, setup-local-ai.ps1, then start.ps1 as described in the README. Do not install dependencies globally when a project environment is available.

The backend entry point is:

.\.venv\Scripts\python.exe server.py

This assumes Ollama is already running. start.ps1 starts or reuses Ollama first. Use one backend process on port 8765 because credentials and request tokens live in process memory.

Frontend changes

React source lives under frontend/src. Rebuild after editing:

cd frontend
npm run build

Then refresh the app at http://127.0.0.1:8765. FastAPI reads the current built HTML and assets without requiring a backend restart for frontend-only changes.

For continuous rebuilding:

npm run build -- --watch

npm run dev provides Vite hot reload, but authenticated API calls require the backend's current process token and the strict Host checks must be respected. The development proxy alone does not establish an authenticated session. The build-and-refresh workflow is the simplest complete local workflow.

Backend changes

After editing Python code, restart the backend. Credentials, request token, and send-attempt tracking are reset; refresh the browser and reconnect Gmail.

Keep the route paths and JSON response fields stable when refactoring, or update React and route tests together. Blocking IMAP, SMTP, and urllib model calls belong in synchronous worker-thread routes unless they are replaced with truly asynchronous clients.

Tests

From the project root:

.\.venv\Scripts\python.exe -m unittest discover -s tests -v

Frontend:

cd frontend
npm test
npm run build

Tests cover mailbox search and thread lookup, request validation, local Host/token protection, model request construction, confirmed sending and duplicate protection, version/edit retention, batch review, connection values, and rendered React controls. Gmail and AI are mocked. Do not add real credentials to test fixtures.

For live verification, connect through the UI with a test account. First verify reads and generation, then save a reviewed test draft. Send only when intentionally testing delivery to an appropriate recipient.

Dependencies and reproducibility

Backend direct dependencies are pinned in requirements.txt; frontend dependencies are recorded in package.json and package-lock.json. Use npm ci to reproduce the frontend installation. .npmrc uses legacy peer resolution to avoid an optional-peer resolver issue encountered with the installed npm version.

When changing dependencies, update the corresponding manifests/lockfile, run the relevant tests and build, and review npm audit. Python transitive dependencies are resolved by pip rather than fully locked.

Git hygiene

Ignored files include model/runtime downloads, virtual environments, node_modules, built assets, package caches, logs, browser preview profiles, and screenshots. Do not commit credentials, mail exports, real reply contents, or process tokens.

A typical change workflow:

  1. Make a focused change and update applicable docs.
  2. Run the relevant tests and production build.
  3. Check git status and git diff for unrelated or sensitive content.
  4. Commit source, tests, manifests and documentation.
  5. Push to the intended branch.

There is no configured deployment pipeline or automatic test workflow in this repository. The app runs locally with the supplied scripts.

Documentation website

The online documentation is generated from README.md and the Markdown guides in docs/. Screenshots are in docs/images/. After editing a guide, rebuild and commit the generated pages:

.\.venv\Scripts\python.exe -m pip install -r requirements-docs.txt
.\.venv\Scripts\python.exe tools/build-docs.py
.\.venv\Scripts\python.exe -m http.server 8877 --directory docs

Preview at http://localhost:8877/. The live site is https://alizainappedology.github.io/reply-desk-docs/. Because the application repository is private, GitHub Pages publishes a separate public documentation-only repository: alizainappedology/reply-desk-docs, main branch, root folder. To publish updates, copy the generated HTML files, site.css, site.js, .nojekyll, and images/ from docs/ into that repository and push main. Do not copy app source, credentials, or local configuration.
